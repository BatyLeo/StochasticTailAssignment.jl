StochasticTailAssignment.FlightDelayModel.SHIFT_TO_AVOID_ZERO — Constant

Small positive shift added to the standard deviation of the departure/arrival intrinsic delay distributions, avoiding a degenerate zero-variance LogNormal/Normal distribution.

StochasticTailAssignment.FlightDelayModel.DelayCoefficients — Type
struct DelayCoefficients

Handcrafted coefficients parameterizing the intrinsic (root) delay distributions of SyntheticDelayModel: one DelayEffects per weight vector of a HandcraftedDelayPredictor, a shared per-airport effect table, and the dynamic-simulator-only beta_* coefficients.

The beta_*_propagated, beta_dep_has_propagated and beta_arr_has_departure_delay coefficients are only used by the dynamic simulator (propagate_delays for SyntheticDelayModel), never by sample_root_scenarios. They default to 0.0, meaning the root delay model is purely static (route-independent). Setting them to nonzero values makes the resulting delays route-dependent, which is only valid for simulation, not as an input to stochastic_column_generation.

Fields

  • mu_dep::StochasticTailAssignment.FlightDelayModel.DelayEffects: departure mu effects, pre-activation (log-minutes)

  • sigma_dep::StochasticTailAssignment.FlightDelayModel.DelayEffects: departure sigma effects, pre-activation (log-minutes)

  • mu_arr::StochasticTailAssignment.FlightDelayModel.DelayEffects: arrival mu effects (minutes)

  • sigma_arr::StochasticTailAssignment.FlightDelayModel.DelayEffects: arrival sigma effects, pre-activation (minutes)

  • airport_effects::Dict{String, Float64}: per-airport departure effect table (log-minutes, mean 0)

  • airport_arr_target_sd::Float64: target standard deviation of the per-airport arrival effect table (minutes)

  • beta_dep_has_propagated::Float64: departure mu effect of a nonzero upstream propagated delay (dynamic simulator only)

  • beta_dep_propagated::Float64: departure mu effect of the upstream propagated delay value, per hour (dynamic simulator only)

  • beta_arr_has_departure_delay::Float64: arrival mu effect of a nonzero departure delay (dynamic simulator only)

  • beta_arr_propagated::Float64: arrival mu effect of the departure delay value, per hour (dynamic simulator only)

StochasticTailAssignment.FlightDelayModel.DelayEffects — Type
struct DelayEffects

Named per-leg effects making up one weight vector (mu_dep, sigma_dep, mu_arr or sigma_arr) of DelayCoefficients, all expressed relative to the population baseline of that component (base, or the tau/population_variance heterogeneity identity for the sigma components) and mean-centered by compile_weights so that they only redistribute delay across legs, without shifting the population mean.

Fields

  • base::Float64: population baseline of the component (component units, pre-activation for mudep and sigmadep/sigma_arr)

  • hub::Float64: hub effect amplitude (component units)

  • airport::Float64: own-airport effect amplitude, applied to the per-airport effect table (component units)

  • cross_airport::Float64: other-airport (cross) effect amplitude, applied to the per-airport effect table (component units)

  • hours::NTuple{5, Float64}: hour-of-day effect for the 00h-05h, 06h-09h, 10h-13h, 14h-17h and 18h-23h bands, in order (component units)

  • days::NTuple{7, Float64}: day-of-week effect, Monday to Sunday, in order (component units)

  • duration::Float64: duration effect, per hour of deviation from a 5h reference duration (component units)

  • tau::Float64: across-leg heterogeneity standard deviation of the mean, measured at risk_spread = 1 (component units, sigma components only)

  • population_variance::Float64: population variance target used to re-derive the within-leg sigma base (component units squared, sigma components only)

struct DelayScenarios{T, R1, R2, F}

Precomputed standard normal scenarios for a given schedule, used through the reparameterization trick to sample intrinsic delays.

Fields

  • schedule::StochasticTailAssignment.AircraftRoutingBase.ActivitySchedule: associated schedule to store scenarios on

  • departure_scenarios::Matrix: matrix of precomputed standard normal draws for departure, size nb_legs x nb_scenarios

  • arrival_scenarios::Matrix: matrix of precomputed standard normal draws for arrival, size nb_legs x nb_scenarios

  • departure_reparameterize::Any: method transforming a scenario draw and distribution parameters into a departure intrinsic delay

  • arrival_reparameterize::Any: method transforming a scenario draw and distribution parameters into an arrival intrinsic delay

  • static_features::Any: static features (shared between departure and arrival), size nb_features x nb_legs

  • feature_names::Vector{String}: names of the static features (from the FeaturesConfig used to build the scenarios), used to check consistency against a SyntheticDelayModel's predictor

StochasticTailAssignment.FlightDelayModel.DelayScenarios — Method
DelayScenarios(
    schedule::StochasticTailAssignment.AircraftRoutingBase.ActivitySchedule;
    nb_scenarios,
    departure_reparameterize,
    arrival_reparameterize,
    config,
    seed
) -> StochasticTailAssignment.FlightDelayModel.DelayScenarios{Float32, typeof(StochasticTailAssignment.FlightDelayModel.lognormal_reparameterize), typeof(StochasticTailAssignment.FlightDelayModel.normal_reparameterize), Matrix{Float32}}

Custom constructor for DelayScenarios: draws nb_scenarios standard normal scenarios per leg of schedule, column by column, from two dedicated Random.Xoshiro random number generators, seeded respectively from hash((seed, :departure)) and hash((seed, :arrival)) (so that increasing nb_scenarios never changes the earlier columns, and so that the arrival stream of a given seed never collides with the departure stream of another seed), and computes the static features of every leg using config.

StochasticTailAssignment.FlightDelayModel.HandcraftedDelayPredictor — Type
struct HandcraftedDelayPredictor

Linear, handcrafted predictor for the intrinsic (root) delay distribution parameters (see departure_prediction and arrival_prediction), with weights compiled once from named, interpretable DelayCoefficients rather than learned.

Since one-hot feature blocks always sum to 1 for a given leg, population baselines are injected as a uniform addition over the DayOfWeek one-hot block of the relevant weight vector (see compile_weights): this acts as an intercept without requiring a dedicated bias feature.

Fields

  • w_mu_dep::Vector{Float32}: weight vector for the departure mu parameter, pre-activation

  • w_sigma_dep::Vector{Float32}: weight vector for the departure sigma parameter, pre-activation

  • w_mu_arr::Vector{Float32}: weight vector for the arrival mu parameter

  • w_sigma_arr::Vector{Float32}: weight vector for the arrival sigma parameter, pre-activation

  • feature_names::Vector{String}: names of the static features, aligned with the weight vectors

  • coefficients::StochasticTailAssignment.FlightDelayModel.DelayCoefficients: coefficients used to compile the weight vectors

StochasticTailAssignment.FlightDelayModel.SyntheticDelayModel — Type
struct SyntheticDelayModel{P}

Synthetic delay model: a HandcraftedDelayPredictor together with the shift, clamp and intensity parameters turning its LogNormal/Normal parameter predictions into intrinsic (root) departure and arrival delays.

has_dynamic_features reports whether any beta coefficient is nonzero, and if so only propagate_delays may be used.

Fields

  • predictor::Any: predictor mapping static features to LogNormal/Normal distribution parameters

  • dep_shift::Float64: positive shift of the root departure LogNormal (minutes)

  • arr_shift::Float64: positive shift of the root arrival Normal (minutes)

  • max_dep::Float64: maximum departure root delay allowed (minutes)

  • max_arr::Float64: maximum arrival root delay allowed (minutes)

  • delay_intensity::Float64: global multiplier applied to every root delay after shift and cap

StochasticTailAssignment.FlightDelayModel._airport_weights — Method
_airport_weights(airports::AbstractVector{String}) -> Dict

Assumed long-run per-airport usage weights (summing to 1) for airports (first(airports) is the hub, every other code an equally likely spoke), matching the stationary distribution of the random-walk instance generator (hub -> uniformly random spoke, spoke -> hub with probability DEFAULT_HUB_FRACTION, else another uniformly random spoke). Returns Dict(hub => 1.0) if airports has no spoke.

Used to center the per-airport and hub effects of DelayCoefficients so that they average out to 0 on a realistically hub-skewed schedule, rather than under a naive uniform-over-airports assumption.

StochasticTailAssignment.FlightDelayModel._base_weight — Method
_base_weight(
    effects::StochasticTailAssignment.FlightDelayModel.DelayEffects,
    risk_spread::Real,
    component::Symbol
) -> Any

Population baseline (intercept, pre-activation) of one weight vector compiled by compile_weights for component (:mu_dep, :sigma_dep, :mu_arr or :sigma_arr).

For the two mu components, this is simply effects.base (risk_spread does not apply to the population baseline itself, only to the per-leg effects around it). For the two sigma components, effects.base is unused: the baseline is instead re-derived from the law-of-total-variance identity (risk_spread * effects.tau)^2 + sigma_base^2 + sigma_legs_variance = effects.population_variance (see _sigma_legs_variance), erroring out with a clear message if risk_spread is so large that the heterogeneity and sigma-variance terms alone would reach or exceed the population variance target.

StochasticTailAssignment.FlightDelayModel._check_feature_layout — Method
_check_feature_layout(
    scenarios::StochasticTailAssignment.FlightDelayModel.DelayScenarios,
    model::StochasticTailAssignment.FlightDelayModel.SyntheticDelayModel
)

Check that scenarios and model.predictor were built from the same FeaturesConfig (same feature names, in the same order), throwing a clear error otherwise.

A mismatch (e.g. DelayScenarios built with the default airport list while model was built with schedule_airports(schedule), or the reverse) silently misaligns every feature-weight dot product, so this should always be checked before combining a DelayScenarios and a SyntheticDelayModel.

_sigma_legs_variance(
    effects::StochasticTailAssignment.FlightDelayModel.DelayEffects,
    risk_spread::Real
) -> Any

Approximate the across-leg variance of the (linearized) within-leg sigma induced by the hub and duration effects of effects, assuming the underlying features are mutually independent: the hub/spoke indicator (Bernoulli, mean POP_HUB_FREQUENCY) and the leg duration (standard deviation POP_DURATION_SD hours). Both effects are scaled by risk_spread, matching how they enter the weight vector in compile_weights.
