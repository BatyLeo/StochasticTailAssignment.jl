    min_turn_time,
    max_turn_time,
    tight_turn_fraction,
    aircraft_type
)

Pad legs up to target legs by appending legs to the tail of existing rotations (described by rotation_tails, a vector of (airport, time) states as returned by _generate_rotation!), instead of creating brand new hub departures that would require hidden extra aircraft.

At each step, the rotation with the earliest last arrival time is extended first (from its current airport, after a random turn time, to the hub or a spoke). A rotation that cannot take another leg before horizon_end is dropped from consideration. If no rotation can take more legs, padding stops early and length(legs) stays below target: callers must tolerate a leg count slightly below the requested one in that case.

StochasticTailAssignment.InstanceGenerator.build_delay_model — Method
build_delay_model(
    schedule::StochasticTailAssignment.AircraftRoutingBase.ActivitySchedule;
    coefficients,
    delay_intensity,
    risk_spread,
    config
) -> StochasticTailAssignment.FlightDelayModel.SyntheticDelayModel{StochasticTailAssignment.FlightDelayModel.HandcraftedDelayPredictor}

Build a SyntheticDelayModel for schedule, using a HandcraftedDelayPredictor compiled from coefficients (pass a custom per-airport effect table via coefficients=DelayCoefficients(; airport_effects=...)).

delay_intensity globally scales every intrinsic root delay after shift and cap (see SyntheticDelayModel). risk_spread scales every named per-leg effect of coefficients and re-derives the within-leg sigma so that the population-level delay distribution stays approximately unchanged while the spread of delay risk across legs increases (see DelayCoefficients).

The returned model is static-only (has_dynamic_features(model) == false), so it is a valid input to sample_root_scenarios and, through generate_root_delays, to stochastic_column_generation.

default_nb_aircraft(nb_legs::Int64) -> Int64

Default nb_aircraft for a schedule with nb_legs legs, max(2, nb_legs ÷ 15), giving a legs-per-aircraft ratio of approximately 15, a ratio typical of short and medium haul operations, while ensuring feasibility across all instance sizes (50 to 600+ legs).

StochasticTailAssignment.InstanceGenerator.generate_benchmark_instance — Method
generate_benchmark_instance(

    nb_extra_aircraft,
    airports,
    aircraft_type,
    horizon_days,
    nb_scenarios,
    delay_intensity,

    delay_coefficients,
    nb_seats,
    seed,
    delay_seed,
    store_arc_index
) -> Tuple{StochasticTailAssignment.AircraftRoutingBase.ActivitySchedule{MetaGraphsNext.MetaGraph{Int64, Graphs.SimpleGraphs.SimpleDiGraph{Int64}, String, Vector{Float64}, Float64, String, MetaGraphsNext.var"#MetaGraph##10#MetaGraph##11", Float64}, G1, StochasticTailAssignment.AircraftRoutingBase.Leg} where G1<:MetaGraphsNext.MetaGraph, Any, PiecewiseLinearFunctions.PiecewiseLinearFunction{Float64}}

Generate a complete benchmark instance ready for solving and evaluation.

Returns (schedule, root_delays, delay_cost_function) where:

  • schedule is an ActivitySchedule with nb_legs legs, or slightly fewer, see generate_legs
  • root_delays is an S x L Matrix{Float32} of root delays
  • delay_cost_function is a piecewise linear delay cost function (medium-haul slopes, weighted by nb_seats)

The default nb_aircraft is default_nb_aircraft(nb_legs), plus nb_extra_aircraft (only applied when nb_aircraft is not given explicitly).

root_delays is generated by generate_root_delays, forwarding delay_intensity, risk_spread and delay_coefficients (see build_delay_model and DelayCoefficients), with a delay seed of seed + 100 by default (override via delay_seed if a caller needs to reproduce this exact draw, e.g. to also sample the unmerged departure/arrival components with sample_root_scenarios_unmerged).

delay_cost_function uses the medium-haul slopes (FlightDelayModel.DELAY_COST_SLOPE_MEDIUM_HAUL) multiplied by nb_seats. Delay cost slopes are expressed per seat and per minute, and are scaled by the aircraft seat count. The default nb_seats=180 matches a typical narrow-body aircraft, nb_seats=1 recovers the unweighted (per-seat) slopes.

    min_flight_duration,
    max_flight_duration,
    hub_fraction,
    seed
)

Generate a vector of nb_legs random Legs with realistic airline structure.

Legs are generated by simulating nb_aircraft aircraft performing rotations from a hub-and-spoke network. Each aircraft performs a variable number of legs (drawn from a Dirichlet-like distribution), creating realistic route length variability. The hub airport (first in airports) attracts most traffic via hub_fraction.

Flight durations vary by destination distance: hub-spoke legs use the full duration range, while spoke-spoke legs use shorter durations.

Each rotation stops as soon as its next leg would land after the horizon, and any shortfall is padded by extending the tail of existing rotations (never by creating new, disconnected hub departures). In the rare case where no rotation has room left before the horizon, padding stops early and the returned vector can have slightly fewer than nb_legs legs.

StochasticTailAssignment.InstanceGenerator.generate_root_delays — Method
generate_root_delays(
    schedule::StochasticTailAssignment.AircraftRoutingBase.ActivitySchedule;
    nb_scenarios,
    seed,
    delay_intensity,
    risk_spread,
    coefficients
) -> Any

Generate an nb_scenarios x nb_legs(schedule) matrix of root delays (in minutes), compatible with propagate_delays_from_root_delays and full_cost(routes, root_delays, instance; delay_cost_function).

Delays are generated from a SyntheticDelayModel (see build_delay_model): for each leg, the root delay in a given scenario is the sum of a departure intrinsic delay (LogNormal) and an arrival intrinsic delay (Normal), whose parameters depend on handcrafted, interpretable static features of the leg (hub/spoke airports, day of week, hour of day, duration). Negative root delays are not clamped to zero, since they represent early legs and are handled correctly by the delay propagation equations (they provide extra slack absorption).

See DelayCoefficients for the default model parameters, and delay_intensity/risk_spread in build_delay_model for the two global knobs exposed here.

StochasticTailAssignment.InstanceGenerator.minimum_fleet_size — Method
minimum_fleet_size(
    legs::Vector{<:StochasticTailAssignment.AircraftRoutingBase.AbstractLeg};
    TTM_factor
) -> Any

Compute the minimum number of aircraft needed to cover all of legs, i.e. the minimum path cover of the leg chaining DAG (an edge u -> v exists whenever v could immediately follow u on the same aircraft, per is_valid_chaining).

By König's theorem, the minimum path cover of a DAG equals the number of vertices minus the size of a maximum matching of the bipartite graph obtained by splitting each vertex into an "out" and an "in" copy. The matching is computed with a simple Kuhn augmenting-path algorithm, which is fast enough for the instance sizes generated here.
